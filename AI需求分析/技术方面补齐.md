# 需求分析师技术知识补充路线

> [!info] 学习目标  
> 面向软件需求分析师、业务分析师（BA）及 B 端产品岗位，快速补齐技术基础，提高技术沟通能力、需求分析准确性和面试专业度。
> 
> **学习原则：** 不追求掌握所有底层实现，重点理解技术原理、适用场景、系统约束以及如何转化为可验证的需求。
> 
> **实践项目：** ReqFlow AI

## 一、技术知识学习优先级

|优先级|知识领域|必须掌握的概念|
|---|---|---|
|P0|系统架构基础|前后端、服务端、客户端、数据库、同步/异步、部署|
|P0|API 与 HTTP|GET/POST、请求响应、JSON、状态码、认证与授权|
|P0|数据库与 SQL|CRUD、主外键、JOIN、事务、索引、数据一致性|
|P1|性能与可靠性|并发、QPS、响应时间、P95、可用性、故障恢复|
|P1|AI 应用工程|Prompt、Token、RAG、结构化输出、幻觉、人工审核|

**优先级说明：**

- **P0（最高优先级）**：求职和项目开发过程中需要优先补齐的基础知识。
    
- **P1（第二优先级）**：具备 P0 基础后，结合 ReqFlow AI 实践逐步深入。
    

## 二、推荐学习资源

### 1. MDN — HTTP Overview

- **官网：** [https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)
    
- **优先级：** P0
    
- **学习方向：** Web 开发基础、HTTP、API 通信
    

**重点学习：**

- HTTP 请求与响应机制
    
- GET / POST 等请求方法
    
- HTTP 状态码
    
- JSON 数据格式
    
- 前端与后端如何通信
    
- 身份认证与授权的区别
    

**学习目标：**

能够解释前端如何通过 API 向后端发送请求，后端如何处理请求并返回数据。

**ReqFlow AI 实践：**

理解用户提交原始需求后，数据如何从前端传递至后端，并保存至数据库。

### 2. SQLBolt — Interactive SQL Lessons

- **官网：** [https://sqlbolt.com/](https://sqlbolt.com/)
    
- **优先级：** P0
    
- **学习方向：** SQL、关系型数据库、数据操作
    

**重点学习：**

- SELECT 数据查询
    
- INSERT 数据插入
    
- UPDATE 数据更新
    
- DELETE 数据删除
    
- JOIN 多表关联查询
    
- 主键与外键
    
- 基础数据表设计
    

**学习目标：**

能够独立编写基础 SQL，理解数据库表结构及数据关联关系。

**ReqFlow AI 实践：**

使用 SQLite 设计需求记录表、需求澄清记录表和审核记录表，实现需求数据的增删改查。

### 3. AWS Well-Architected Framework

- **官网：** [https://docs.aws.amazon.com/wellarchitected/](https://docs.aws.amazon.com/wellarchitected/)
    
- **优先级：** P1
    
- **学习方向：** 系统架构、可靠性、安全性、性能
    

**重点学习：**

- Reliability（可靠性）
    
- Security（安全性）
    
- Performance Efficiency（性能效率）
    
- 系统故障与恢复机制
    
- 数据安全与访问控制
    
- 性能指标与架构约束
    

**学习目标：**

能够理解常见的系统质量属性，并将其转化为合理、可测试的非功能需求（NFR）。

**ReqFlow AI 实践：**

为 ReqFlow AI 编写性能、安全、可靠性相关的 NFR，并设计对应测试场景。

### 4. IIBA — The Business Analysis Standard

- **官网：** [https://www.iiba.org/knowledgehub/the-business-analysis-standard/](https://www.iiba.org/knowledgehub/the-business-analysis-standard/)
    
- **优先级：** P0（需求分析专业知识）
    
- **学习方向：** 商业分析、需求工程、需求管理
    

**重点学习：**

- Business Requirements（业务需求）
    
- Stakeholder Requirements（干系人需求）
    
- Solution Requirements（解决方案需求）
    
- Requirements Validation（需求确认）
    
- Requirements Traceability（需求追踪）
    
- Solution Evaluation（解决方案评估）
    

**学习目标：**

建立更加规范的需求分析思维，理解如何从业务问题出发，形成可追踪、可验证的需求，并评估交付结果。

**ReqFlow AI 实践：**

完成从 Problem → Need → Requirement → Solution 的完整分析，逐步形成 BR、UR、FR、NFR、PRD 和验收标准。

### 5. Google SRE — Monitoring Distributed Systems

- **官网：** [https://sre.google/sre-book/monitoring-distributed-systems/](https://sre.google/sre-book/monitoring-distributed-systems/)
    
- **优先级：** P1
    
- **学习方向：** 系统监控、性能、可靠性
    

**重点学习：**

- Latency（延迟）
    
- Traffic（流量）
    
- Errors（错误）
    
- Saturation（资源饱和度）
    
- 响应时间与吞吐量的区别
    
- 系统性能指标的衡量方法
    

**学习目标：**

避免混淆并发用户数、QPS、响应时间、请求成功率等指标，能够更专业地描述和讨论系统性能要求。

### 6. OpenAI — Structured Outputs

- **官网：** [https://developers.openai.com/api/docs/guides/structured-outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
    
- **优先级：** P1
    
- **学习方向：** LLM API、JSON Schema、结构化数据输出
    

**重点学习：**

- LLM API 调用基础
    
- Prompt 设计
    
- JSON Schema
    
- Structured Outputs（结构化输出）
    
- 输出格式校验
    
- 模型幻觉与人工审核
    

**学习目标：**

理解如何将 LLM 的自然语言输出转换为符合指定结构的数据，以及如何验证输出的正确性。

**ReqFlow AI 实践：**

用户输入自然语言需求后，使用 LLM 生成结构化需求、澄清问题和候选需求分类，再交由人工审核确认。

---

## 三、学习原则

- 每天安排约20分钟补充技术知识。
    
- 优先学习 P0，再根据实际项目需要学习 P1。
    
- 不追求一次性掌握所有技术细节。
    
- 每学习一个重要概念，都尝试用自己的语言解释。
    
- 将理论知识与 ReqFlow AI 产品实践结合。
    
- 面试中区分已知事实、合理假设和待确认事项。
    

**最终目标：** 具备与开发、测试和架构人员有效沟通的技术理解能力，能够准确分析业务需求、识别技术约束，并独立解释产品设计决策。
